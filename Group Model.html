Introduction

This notebook addresses a donor analytics problem for PBS Utah: identify which constituents are most likely to give at least $1,200 in the next fiscal year and estimate likely giving ranges for those probable donors. The business objective is to support more efficient solicitation planning by combining giving history, campaign interactions, cultivation activity, and passport engagement.

The analytic problem has two parts. First, a supervised classification step estimates the probability a constituent-year will become a $1,200+ donor in the following year. Second, for likely positive cases, a multiclass model estimates the most probable next-year gift band. In parallel, an unsupervised 5-profile segmentation model (k-means) is included to support donor profiling. The purpose of this notebook is to provide a reproducible workflow from data ingestion and normalization through model comparison, model selection, and interpretation-ready output for decision use.

The core datasets for this EDA are read directly from GitHub so the notebook is reproducible without local files.

2.1 Validate URLs

The GitHub CSVs for this project are LFS-backed, so we use the GitHub media endpoint as a fallback. This code checks whether a URL resolves and returns a usable first line.

resolve_csv_url <- function(path) {
  raw_url <- paste0(
    "https://raw.githubusercontent.com/jefftwebb/donor_prediction_capstone_project/main/",
    path
  )
  media_url <- paste0(
    "https://media.githubusercontent.com/media/jefftwebb/donor_prediction_capstone_project/main/",
    path
  )

  raw_ok <- tryCatch({
    hdr <- read_lines(raw_url, n_max = 1)
    length(hdr) > 0 && !grepl("^version https://git-lfs.github.com/spec/v1$", hdr[1])
  }, error = function(e) FALSE)

  if (raw_ok) return(raw_url)

  media_ok <- tryCatch({
    hdr <- read_lines(media_url, n_max = 1)
    length(hdr) > 0 && !grepl("^version https://git-lfs.github.com/spec/v1$", hdr[1])
  }, error = function(e) FALSE)

  if (media_ok) return(media_url)

  NA_character_
}

2.8 Data Description

  • constituents_w_memberships is the main constituent profile table.
  • unite_payments is the cleanest donation transaction table and is the benchmark format for this EDA.
  • team_approach_legacy_payments contains historical donation records and multiple potential constituent matches, so it will require careful cleaning and expansion before joining.
  • passport_viewing is movie/show-level viewing behavior and should be aggregated before joining to donor-level analytics.
  • campaign_codes is a lookup table for campaign metadata; it should be used to enrich donation data rather than treated as a transaction table.
  • campaign_members contains campaign response history; responded_date may not be reliable and should be used cautiously.
  • cultivation appears to be a portfolio/experimentation table with treatment assignment flags and adoption status.
  • soft_credits records donor attribution credits for gifts made by or on behalf of an entity constituent (e.g., donor advised fund) and should be included in the normalized payment/attribution base.

  • Team Approach legacy payments expanded to one row per non-null constituent match

The objective is a single long-form donor-payment table where each row represents a payment or attribution event tied to a constituent, not a household record.

The raw GitHub URLs in this project are LFS-backed, so the resolver from Section 2 is used here to avoid reading the pointer files instead of the CSVs themselves.

The next stage is supervised modeling on this donor-year frame.

Data Preparation

The modeling frame is built at the constituent-year level. Payment and attribution records from Unite, Team Approach legacy, and soft credits are normalized into one long table, then aggregated to annual giving totals and joined to profile, campaign, cultivation, and viewing features.

For transformations, donor-year outcomes are engineered with lag logic (next_year_giving) and converted into two targets: a binary target_1200 and a multiclass amount_band for positive cases. Categorical predictors are consolidated for rare levels, unknown/missing categories are handled explicitly, and predictors are one-hot encoded for model engines that require numeric matrices.

For missing values, structural missingness is preserved where substantively meaningful. During preprocessing, numeric predictors are median-imputed and nominal predictors are mode-imputed to keep train/test schemas aligned. Logical indicators are converted to 0/1 before matrix-based modeling.

Modeling Process

The modeling approach is two-stage. Stage 1 predicts whether a constituent will give at least $1,200 in the next fiscal year, which matches the PBS Utah major-donor designation threshold (target_1200). Stage 2 then estimates the probability distribution over next-year gift-size bands for the positive cases (amount_band), which supports expected-value ranking and solicitation planning.

Candidate models for Stage 1 (binary target) are penalized logistic regression, elastic net logistic regression, and gradient-boosted trees (XGBoost). Candidate models for Stage 2 (amount band among positive cases) are multinomial regression and multiclass XGBoost.

Model selection uses cross-validation on the training period only. Stage 1 uses stratified v-fold CV with pr_auc, roc_auc, and mn_log_loss; Stage 2 uses stratified v-fold CV with mn_log_loss and accuracy. Hyperparameters are tuned via regular grids (elastic net) and tuning grids (XGBoost), then the best workflow is finalized and refit on the full training split.

Model Performance

For this submission, only the best-performing Stage 1 model and best-performing Stage 2 model are kept in the final scoring pipeline. Performance is reported on both train and test partitions using the same metrics used in cross-validation.

The train/test split is time-based: all earlier fiscal years are used for training and the latest fiscal year is held out for testing. This avoids temporal leakage and better reflects forward-looking deployment.

Runtime is summarized as held-out scoring time for the selected models. Full training and tuning runtime will vary by fast_mode, fold count, and grid size settings.

Performance characteristics are assessed in three ways: discrimination/ranking quality (PR AUC and ROC AUC for Stage 1), probability calibration/loss (multinomial log loss for both stages), and classification accuracy. Train-versus-test comparisons are used to check generalization; large train-test gaps would indicate potential overfitting.

Results

The supervised pipeline produces a ranked solicitation table (final_ranked) containing each held-out constituent-year, predicted probability of $1,200+ giving, predicted gift-band probabilities, and expected next-year giving. This supports a practical triage workflow: prioritize high-probability, high-expected-value records.

As a baseline check, Stage 1 test performance is compared with a majority-class classifier that always predicts the most common training label. This establishes whether the supervised model is adding predictive value beyond a trivial class-frequency rule.

Used together, the two modeling tracks serve different decisions. The supervised model identifies who to prioritize for outreach based on likelihood and expected value, while the k-means profiles provide context for how to tailor outreach by grouping donors with similar giving, engagement, and response patterns. The profile labels are descriptive segments, not causal effects, and should be used as strategy guidance rather than treatment proof.

The k-means 5-profile model adds segmentation context by grouping constituents into behaviorally distinct profiles using giving, campaign, and viewing features. These profiles are not causal drivers, but they can help tailor messaging and stewardship strategy.

Overall, the modeling outputs are decision-oriented: one output for ranking and expected value, and one output for donor profile interpretation.
